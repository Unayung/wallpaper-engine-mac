# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A patched fork of Open Wallpaper Engine — a native macOS app (Swift 5, AppKit + SwiftUI, deployment target 13.0) that renders Wallpaper Engine wallpaper packages on the desktop. It reads Wallpaper Engine's own asset formats (`project.json`, `.pkg`, `.tex`, `scene.json`) but is unaffiliated with the Steam product. See `README.md` for the feature list and the known rendering limitations: multi-pass and audio-reactive effects are declined, video textures show only their first frame, and 3D scenes fall back to their preview.

## Build & run

Single Xcode target, no package manager, no dependencies beyond system frameworks.

```sh
# Build (Debug) into the gitignored build/ directory
xcodebuild -project "Open Wallpaper Engine.xcodeproj" \
  -scheme "Open Wallpaper Engine" -configuration Debug \
  -derivedDataPath build build

# Run the result
open "build/Build/Products/Debug/Open Wallpaper Engine.app"

# Clean
xcodebuild -project "Open Wallpaper Engine.xcodeproj" -scheme "Open Wallpaper Engine" clean
```

- **There is no XCTest target; `scripts/test-scene-runtime.sh` is the one test suite.** It compiles the scene sources with `swiftc` and runs `Tests/SceneRuntimeTests/main.swift`: the script behaviours from upstream 0.9.0 (below), their binding to `WallpaperSKScene`, and fixture checks that run only when `WE_MAPLE_WALLPAPER`, `WE_HAPPYVILLE_WALLPAPER`, `WE_TOY_TOWER_WALLPAPER` or `WE_LITH_HARBOR_WALLPAPER` point at those MapleStory items. 67 checks pass without fixtures. The old test targets are gone from `project.pbxproj` and the shared scheme no longer references them, so `xcodebuild test` stops at once with "Scheme Open Wallpaper Engine is not currently configured for the test action". (With the stale references still in the scheme it failed instead with "There are no test bundles available to test", which read like a broken build.)
- **Scene changes are verified empirically instead**, by `Tools/scenecheck` (see `Tools/README.md`): three standalone tools that compile the app's own scene sources and run them over every wallpaper in `~/Documents/Open Wallpaper Engine`. `render` writes a PNG per scene and flags flat frames, `effects` compiles every translated shader and attributes the failures, `cost` reports milliseconds a frame. Every regression in this subsystem's git log was caught by one of them, so run the relevant one before and after any change to `SceneParsers/` and diff the reports. They are deliberately *not* Xcode targets — each has its own `main.swift` and would break the app build.
- **`Tools/appcheck`** is the same kind of tool for the whole library and all three types. It decodes every manifest, opens every video with AVFoundation, checks every web page's local references, and builds every scene. It exits non-zero on any FAIL, so run it before and after a change to loading, type dispatch or the library listing. It currently reports 148 PASS / 0 FAIL / 7 SKIP (measured 2026-10-27; the count follows the library). It reads the default library folder: its own defaults domain never sees the app's `WallpaperLibraryPath`. The one VP9 video passes through the supplemental decoder `AppDelegate` registers at launch and carries a portability warning (`⚠ codec vp09 needs a decoder not every supported Mac has`), because a Mac without that decoder would show black; see `Tools/README.md`.
- **Signing:** `DEVELOPMENT_TEAM = 35BWY46G6T` with automatic signing and hardened runtime. A different machine needs its own team or "Sign to Run Locally".
- **New source files must be registered in `project.pbxproj`** (classic `objectVersion = 56` project with explicit `PBXBuildFile` entries — no filesystem-synchronized groups). Adding a `.swift` file to a folder does not add it to the build.

## Architecture

### AppKit entry point, not SwiftUI `App`

`main.swift` sets `NSApplication.shared.delegate = AppDelegate.shared` and calls `run()`. There is no `@main` struct. `AppDelegate` is a singleton *and* the composition root: it owns the three view models the whole app shares.

```
AppDelegate.shared
├── contentViewModel        (ContentViewModel)        — library browsing, filters, import, drag/drop
├── wallpaperViewModel      (WallpaperViewModel)      — per-screen assignments + playback control surface
└── globalSettingsViewModel (GlobalSettingsViewModel) — settings + playback *policy*
```

Views reach these through `AppDelegate.shared` rather than through the environment in many places. That creates a real initialization hazard: anything that touches `AppDelegate.shared` cannot run inside a view model's `init()`, because those view models are constructed *by* `AppDelegate.init()` and re-entering the `dispatch_once` for `shared` traps. `WallpaperViewModel.restoreSavedVolume()` exists solely for this reason and is called from `applicationDidFinishLaunching`. Keep new AppDelegate-dependent setup out of `init`.

### Windows

`AppDelegate` creates and owns every window directly:

- **Wallpaper windows** — one borderless `WallpaperWindow` per *enabled* screen, at `CGWindowLevelForKey(.desktopIconWindow) - 1` — not `.desktopWindow`: macOS 27's WindowManager draws the system wallpaper one level above `.desktopWindow` and covered the scene — `[.stationary, .canJoinAllSpaces]`, `ignoresMouseEvents = true`. Held in `wallpaperWindows: [screenId: NSWindow]` and *diffed*, never rebuilt wholesale, by `syncWallpaperWindows()`: a removed or disabled screen loses its window, a new one gets one, an existing one is only re-framed. `didChangeScreenParameters` also fires for resolution changes, rearrangement and Sidecar, and the old wholesale rebuild restarted every video and re-parsed every scene on each of them. `screensChanged()` enables a display only the first time it is seen; a screen the user switched off is remembered in `userDisabledScreens` (`DisabledScreens`) and stays off across reconnects.
- **Main window** — `MainWindowController`, hosting `ContentView`.
- **Settings window** — plain `NSWindow` with an `NSToolbar` (`SettingsToolbarIdentifiers`) hosting `SettingsView`. It applies every change instantly (`GlobalSettingsViewModel.settings.didSet` saves and applies) and has no OK / Cancel and no window delegate: the old pair, an "Edited" badge and a reset-on-close sat over that same `didSet`, so the badge never showed and Cancel reverted nothing. The quality presets are a selection *derived* from the settings (`GlobalSettings.activeQuality`, "Custom" when none matches), at 10/15/20/30 fps because those are distinct and paced exactly on both 60 and 120 Hz (High's old 25 delivered Ultra's 30; a revision-1 save holding exactly the old High preset is decoded as today's High, so it does not open as "Custom"). "Start with macOS" reads `SMAppService.mainApp.status` (`loginItemStatus`, re-read when Settings opens and when the app becomes active) and only the toggle registers or unregisters; `settings.autoStart` is a mirror nothing observes, so adopting the system's state cannot loop back into a register call. Three pages — Performance, General, About — indexed 0/1/2 by `GlobalSettingsViewModel.selection` (the `jumpTo…` actions and `SettingsView`'s switch are the only places holding the numbers). Only working controls are shown: the disabled placeholders and the Plugins page were removed, but their `GlobalSettings` fields stay so saved settings keep their shape, with the reasons each is not implemented (MSAA, process priority, VRAM, crash restart, log level) kept beside the field. The library's GIF animation toggle is `@AppStorage("TestAnimates")`, read by `ExplorerItem`; the key predates its move to General and must not be renamed. General → Library also sets the library folder, and General → Developer shows the two switches that used to be `defaults write`-only — `SceneScriptsDisabled` and `WallpaperEngineAssetsPath` — under the same keys, so Terminal and Settings agree. All three are plain `UserDefaults` keys, not `GlobalSettings` fields, and Reset leaves them alone. Their setters on `GlobalSettingsViewModel` send `objectWillChange` by hand: that is what makes `SceneWallpaperView` recompute its `SceneQuality`, which now carries `scripts` and `assetsRoot`, find it changed and rebuild, exactly as for a quality control.
- **Menus** — main menu and status-bar menu are built in code in `MenuBars/`, not in a nib.

Because wallpaper windows ignore mouse events, web wallpapers get input via a global `NSEvent` monitor in `setEventHandler()` that forwards a *specific* event mask to the `WKWebView` under the cursor — only when Finder is frontmost. Do not widen that mask to `.any`; it starves the main thread.

### Per-screen wallpaper model

A screen is identified by its `CGDirectDisplayID` rendered as a `String` (`WallpaperViewModel.screenId(for:)`). Assignments live in `wallpapers: [String: WEWallpaper]`, enablement in `enabledScreens: Set<String>`, and the screen the UI is currently configuring in `selectedScreenId`. `currentWallpaper` is just sugar for "the selected screen's wallpaper".

Setting a wallpaper from the UI goes through `nextCurrentWallpaper`, whose `willSet` gates `web` and `application` types behind the `TrustedWallpapers` allowlist (showing the unsafe-wallpaper sheet otherwise). Assignments that bypass that gate should call `setWallpaper(_:for:)` directly and mean it.

### Wallpaper rendering: one view + view model per type

`WallpaperView` switches on `project.type` and dispatches to an `NSViewRepresentable`:

| Type | View | Backing | View model |
|---|---|---|---|
| `video` | `VideoWallpaperView` | `AVPlayer` | `VideoWallpaperViewModel` |
| `scene` | `SceneWallpaperView` | `SKView` (SpriteKit) | `SceneWallpaperViewModel` |
| `web` | `WebWallpaperView` | `WKWebView` | `WebWallpaperViewModel` |

Each representable creates its view model in `init` from `wallpaperViewModel.wallpaper(for: screenId)` and reloads in `updateNSView` when the resolved file URL changes.

`WebWallpaperView` sets the private WebKit preferences `allowFileAccessFromFileURLs` / `allowUniversalAccessFromFileURLs` (both underscore and non-underscore variants) through `ObjCExceptionCatcher.performSafe` — a bridged Objective-C helper (`Services/ObjCExceptionCatcher.{h,m}`, exposed via `Open Wallpaper Engine-Bridging-Header.h`) that catches the `NSException` a wrong KVC key would throw. Without those keys WebGL wallpapers render as gray rectangles.

A web wallpaper's content process can die (GPU reset, memory pressure, a page bug), and WebKit then leaves the view blank for good. `WebWallpaperViewModel.webViewWebContentProcessDidTerminate` reloads after 1 s, 5 s and 30 s; on the fourth crash within ten minutes it gives up and shows the preview. The paused still is tied to navigation: every load clears it, and a page loaded while paused runs for about a second (media still suspended) before its still is taken, because an earlier cover captured the page before it had painted, or kept the previous page's frame.

### Playback: control surface vs. policy

Two `@Published` properties on `WallpaperViewModel` — `playRate` and `playVolume` — are the *only* playback control surface. Every wallpaper type subscribes to them: video mirrors them onto its `AVQueuePlayer`; scene mirrors `playRate == 0` onto `SKView.isPaused` and its sound objects (`SceneSoundscape`) onto their `AVAudioPlayer`s; web pushes both into the page through the injected `window.__oweHost` script, holding `requestAnimationFrame` and media while paused and covering the view with a still of its last frame.

Both are *derived* values, never set directly by a policy. `playRate` is `0` while `isUserPaused` or any `autoPauseReasons` entry holds, else the user's slider rate; `playVolume` is `0` while any `autoMuteReasons` entry holds. Each `PlaybackPolicy` (other app focused, fullscreen, on battery, displays asleep, …) owns its own reason, so one policy ending cannot resume what another paused, and none can undo the user's own pause. The menu's Resume / Unmute clear every reason, since they must visibly do something.

Policy lives elsewhere and always acts through `AppDelegate`'s verbs in `MenuBars/StatusBar.swift`:

- `mute()` / `unmute()` / `pause()` / `resume()` — the user's deliberate choice, driven by the status-bar menu, whose items are edited in place from `$playRate` / `$playVolume` (a title comparison broke under zh-Hans).
- `autoMute(_:)` / `autoUnmute(_:)` / `autoPause(_:)` / `autoResume(_:)` — driven by a `GlobalSettings` rule, each with the `PlaybackPolicy` responsible. `autoMute` stashes `volumeBeforeAutoMute`, and `PlayVolume` is never persisted while an auto-mute holds, so quitting in that state cannot make the next launch silent. Never call `mute()` from a policy path. `Stop (free memory)` closes the wallpaper windows outright (`stopReasons`) rather than hiding them.

Only one screen is heard: `WallpaperViewModel.audioScreenId` (the menu-bar display if enabled, else the first enabled one) gets `playVolume`, every other screen plays at 0. Video, web and scene sound all subscribe to `$audioScreenId` alongside `$playVolume`.

`GlobalSettingsViewModel` decides *when*: `activateApplicationDidChange()` for app focus, `displayAsleepDidChange(asleep:)` for screen sleep, and `PlaybackConditionMonitor` for fullscreen apps and battery power (IOPS). The "other application playing audio" rule is `OtherAppAudioMonitor` (macOS 14.2+, disabled with an explanation below): Core Audio process objects, listened to only while the picker is set. Three things about that signal were measured with `Tools/audiocheck` and are easy to get wrong: per-process `IsRunningOutput` never notifies, so listen on `kAudioProcessPropertyIsRunning` and read `IsRunningOutput`; it means "output IO running", which an `AVPlayer` keeps ~7.4 s after `pause()`, so the rule lets go late by design — and a page that holds an output open while silent (an idle `AudioContext` behind a gain of 0, `<audio autoplay muted loop>`) keeps it engaged for as long as the page is open, a false positive no permission-free signal can tell apart; and a web wallpaper's sound runs in WebKit's GPU process, a separate PID, which is excluded by *responsible* PID rather than `getpid()` — otherwise a web wallpaper with sound pauses itself in a loop. iOS Simulator processes hold output open for hours and are excluded by path. No TCC permission is involved. Sleep/wake requires observing **both** notification pairs — `screensDidSleep`/`screensDidWake` *and* `willSleep`/`didWake`. With external displays attached the Mac blanks the screens without ever suspending, so only the `screens*` pair fires; observing `didWake` alone leaves playback stopped until restart. See the comments in `AppDelegate.applicationWillFinishLaunching`.

### Wallpaper library

All packages live in `~/Documents/Open Wallpaper Engine/` unless the user chose another folder in Settings (`WallpaperLibraryPath`), reached only through `FileManager.wallpapersDirectory` (`Services/WallpaperDirectory.swift`), which creates the default directory on demand. Never hardcode the Documents path — an earlier version used raw `~/Documents` and picked up unrelated folders as broken wallpapers. A chosen folder is used only while it exists and is never created (an unmounted volume would otherwise get an empty stand-in under `/Volumes`); while it is missing the default folder is used. So the resolved folder can move with nothing in Settings changing — a drive mounted or ejected, the folder created, renamed or deleted — and `ContentViewModel` re-resolves it, re-opening its watcher if it moved, on every `refresh()`, on `NSWorkspace` mount/unmount, and when the watched folder reports `.delete`/`.rename`/`.revoke` (the last is all an `O_EVTONLY` descriptor gets when its volume is unmounted). Changing the folder moves and deletes nothing: `ContentViewModel.libraryDirectoryDidChange` re-opens the folder watcher on the new folder and refreshes, a screen showing a wallpaper from the old folder keeps it (`ScreenWallpapers` holds absolute paths and the files are still there), and Workshop imports go to whichever folder is current when the copy starts. See `GlobalSettingsViewModel.setWallpapersDirectory`.

`ContentViewModel` exposes the library as a chain of *computed* properties: `urls` → `allWallpapers` → `searchedWallpapers` → `filteredWallpapers` → `sortedWallpapers` → `autoRefreshWallpapers`. Every access re-reads the directory and re-decodes every `project.json`; `refresh()` snapshots the result into the `@Published wallpapers` array. Be aware of the cost before calling these in a tight loop or a view body.

`allWallpapers` lists only what the user can pick: a Workshop preset (a manifest with no `type`, a settings override for another item) and an entry with no `project.json` (typically a dead symlink into steamcmd's `workshop/content`) are left out of the grid, not shown as "Error" tiles, while a manifest that declares a type but fails to decode stays visible as invalid. `setWallpaper(_:for:)` refuses an invalid one outright. (A merge once replaced the filter with a plain `map` and nine Error tiles came back. `Tools/appcheck` counts these as SKIP by the same rules.)

Filters are `OptionSet`s in `ContentView/ViewModels/FilterResultsViewModel.swift` (`FRType`, `FRAgeRating`, `FRShowOnly`, …), persisted via `@AppStorage`. Note the asymmetry: `FRShowOnly` is a *restriction* set, so empty means "no restriction" — it must be tested as `showOnly.contains(.approved) && !wallpaper.approved → hide`, not the other way round. `FRTag` and `FRSource` follow the same rule for the opposite reason: their boxes start all ticked like `FRType`'s, but an empty selection (or one holding only bits no option uses any more) means "no restriction", so a stored value can never empty the grid. `FRType` and `FRAgeRating` are plain inclusion sets, where unticking everything hides everything.

What the sidebar offers, and where each answer comes from:

- **Tags** — project.json's `tags`, matched against the `FRTag` labels after lower-casing and dropping non-alphanumerics ("Pixel art" = "Pixel Art"); a wallpaper with no recognised genre counts as Unspecified. Every tag in the measured library maps to an option. The filter logic existed for a while behind a `.disabled(true)` that greyed the whole section out.
- **Source** — `FRSource.of`: Workshop when project.json has a `workshopid` *or* the folder is named by a Workshop id — all digits *and at least nine of them* (`FRSource.isWorkshopFolderName`; steamcmd imports land in `<library>/<id>`, and 76 of the 136 Workshop items carry no `workshopid`), My Wallpapers otherwise (bare videos, zips, own folders: 12). The length floor exists because a bare-video import names its folder after the clip and writes no `workshopid`, so `20231015.mp4` used to be filed under Workshop; the importer also prefixes "Video " to any clip name the test would accept, so a timestamp-named clip cannot get there either. Wallpaper Engine's third source, "Official", was dropped — nothing in a package says it shipped with Wallpaper Engine. Bits keep their old positions.
- **Resolution** — removed, not implemented. The data exists (scenes: `general.orthogonalprojection` in scene.json; videos: track size; all 148 resolve), but reading it uncached costs 25–36 ms for the scenes and 57–61 ms for the videos per refresh, against 4.5 ms for the whole chain, on the main thread; and the 21 boxes are Workshop tags whose "Standard"/"Other" thresholds Wallpaper Engine does not publish — 45 of the 148 sizes fall on no listed resolution. Doing it would mean an off-main index keyed by path + mtime *and* inventing the buckets. The measurements are in the comment above `FRSource`; the old `FR*Resolution` defaults keys are no longer read.

### `project.json` handling

`WEProject` (`Services/WEProject.swift`) models only a handful of keys, so encoding it back to disk **silently drops** `ratingsex`, `ratingviolence`, every user property other than `schemecolor`, and anything else a Workshop author wrote. Any edit to an existing `project.json` must go through `ProjectJSONPatch`, which round-trips the file as a plain `[String: Any]` and rewrites just the target key. Full `WEProject` encoding is only appropriate when *creating* a project file from scratch (e.g. importing a bare `.mp4`).

### Scene wallpapers (`Services/SceneParsers/`)

The resolution chain, implemented across `SceneWallpaperViewModel`, `PKGParser`, and `TEXParser`:

```
project.json .file (scene.json)
  → scene.pkg (PKGV archive; falls back to loose files)
    → scene.json → objects[]
      → model JSON (.json) → material JSON → texture name
        → <name>.tex (TEXV0005 → TEXI metadata → TEXB image data)
          → NSImage → SKSpriteNode
```

Three lookup roots are tried in order for every asset: the wallpaper's `.pkg`, loose files in the wallpaper directory, then the **shared Wallpaper Engine asset library** (`~/Library/Application Support/Steam/steamapps/common/wallpaper_engine/assets`, overridable via the `WallpaperEngineAssetsPath` default, set from Settings → General → Developer and used only while it exists). `WEAssetLibrary` resolves it for every build, and it travels in `SceneQuality.assetsRoot`, so a change rebuilds the scenes showing; it used to be a `static let`, frozen at launch. Scenes reference `models/util`, `materials/util`, and `particles/presets` from that library without ever bundling them, so those layers silently fail to resolve when Wallpaper Engine is not installed.

`TEXParser` parses the real container rather than scanning for magic bytes. `freeImageFormat >= 0` means the mipmap payload is a whole JPEG/PNG file; `-1` means raw pixels, usually LZ4-block compressed, in the TEXI format (0 = RGBA8888, 4/6/7 = DXT5/DXT3/DXT1, plus undocumented values that are simply 1 or 2 bytes per pixel). The TEXB header gained fields across revisions 0001→0004, and the revision string does not reliably predict which are present, so every known shape is tried and the one whose declared size matches the pixel count wins. Textures are stored padded to a power of two and must be cropped back to the TEXI dimensions. When no image layer resolves at all, `buildSKScene` falls back to `preview.jpg/png/gif`.

**Sprite sheets play only when nothing else picks their frame.** `TEXParser.extractFrames()` cuts a TEXS sheet into frames with their display times (seconds, as upstream 0.9.0 reads them), and `WallpaperSKScene.tickSprites` steps them — but only for a table that came through whole (13 of 99 have frames past their image edge and misalign after frame 5), and never for a layer a script reaches through `getTextureAnimation()` (`scriptedTextureAnimations`, searching every field's script: Lost Landscape's day/night switch drives it from `angles`). Those sheets are *states* — a shuffle button, Lonely Cat's AM/PM, a play/pause morph — and on the clock they flicker; the runtime offers no texture animation, so they keep frame 0. Of 6 whole sheets on image layers, 2 play: Retro Room's Donkey Kong screen and the Samurai's walk. Particles still use frame 0.

**Video textures stay in the layer's own blend mode.** Upstream 0.9.0 composites every video texture additively, on the grounds that the MP4s are opaque and their black backgrounds cover the scene. Measured here against the previews (mean grey-level difference at 96×54): additive is worse on Valley (20.7 → 31.8, its fog is already `screen`) and Hacker Apartment (19.1 → 27.4, the skyline *is* the background), equal on Pixels, and better only on Lancer X (74.1 → 55.4), whose full-frame intro video — the "LOADING" screen — is what hides its whole scene. That one is an intro-video problem, not a blend-mode one.

**A `.tex` can hold a whole MP4**, and nothing in the header says so — TEXI still reports format 0 (rgba8888) and TEXB still reports `freeImageFormat` -1 ("raw pixels"), so the payload has to be sniffed for the ISO-BMFF `ftyp` box at bytes 4–7. Seven textures across four scenes do this (Valley, Pixels, 2000s Hacker Apartment, Mitsubishi Lancer X), and every one of them also carries bit `0x20` in the TEXI flags while no other texture out of 1195 does — but the payload signature is what `TEXParser.isISOBMFF` checks, because a payload cannot be wrong about what it is. The detection has to precede the raw-pixel path and return unconditionally, because that path does not *fail* on a video: it divides payload bytes by pixel count and hands the quotient to `expandRaw`. Valley's fog came out at exactly 1 byte per pixel and its H.264 bitstream was drawn as grey static over the whole wallpaper; Hacker Apartment's 4K skyline divided out to 3 and came back as RGB static. Failing silently would have been bad — producing *convincing* noise was worse, because a wallpaper full of static reads as a mis-composed scene and sends you looking for the bug in the compositor.

`TEXParser.firstVideoFrame` decodes frame 0 with `AVAssetImageGenerator`. AVFoundation will not read a video out of memory, so the payload is staged to a temp file, which **must** carry a `.mp4` extension — a file URL is typed by its path extension, and an extensionless one comes back with an empty track list and no error. Cost is 13–50 ms per texture including the write, unrelated to size (27 MB 4K: 50 ms; 2.5 MB 1080p: 44 ms — what is paid for is opening a decoder), plus ~150 ms of one-off codec warm-up per process. All of it is load-time.

**Live video (`SKVideoNode`) is deliberately not done, and the reason is measurement, not cost.** An `SKVideoNode` renders nothing through `SKRenderer` — measured at 0.000 non-black pixels while the player's own clock advanced to 2.84 s — but renders correctly in a real `SKView` (0.919). Every tool in `Tools/scenecheck` is built on `SKRenderer`, so live video would make those seven layers invisible to the only instrument this project has: `render` would show holes where the fix now shows artwork, and `cost` would silently under-report. The second obstacle is playback control: `SceneWallpaperView` mirrors `playRate == 0` onto `SKView.isPaused`, and that does **not** stop an `AVPlayer` feeding a video node — measured, the player ran 4.22 → 6.24 s with `isPaused` set. Each node would need its own `$playRate` subscription in the manner of `VideoWallpaperViewModel`. A still first frame keeps these layers inside the verifiable envelope; the two scenes that lose most from it are the ones whose video *is* the motion (Hacker Apartment's skyline, Valley's drifting fog).

Scene JSON is polymorphic: many fields are either a plain value or `{"script": .., "value": ..}`. Decoding is deliberately lenient (`try?` per field, `decodeFlexible`) — a strict `Codable` conformance will fail on real Workshop content. Vector/color strings are parsed by the `String.parseVector2/parseVector3/parseColor` helpers in `SceneModels.swift`. Coordinates need flipping: Wallpaper Engine uses a top-left origin with Y-down, SpriteKit uses bottom-left with Y-up.

**A `{"user": .., "value": ..}` field's `value` is stale; the project's is the real one.** The `value` is what the user property held when the author last saved the scene, and what Wallpaper Engine applies is `general.properties.<key>.value` in `project.json`. 283 of the library's 2306 bindings differ, in 24 scenes: Samurai's moon was authored red and is set white, Hacker Apartment's grain and sharpen were authored on and are set to 0, and the clocks' 12/24-hour and date-format flags differ too. `SceneUserProperties` reads the project raw with `JSONSerialization` (never through `WEProject`, never written back) and travels in `JSONDecoder.userInfo`. Every wrapper resolves its `user` key where it already reads `value`, including the `{"user": {"name": .., "condition": ..}}` combo form. So a new wrapper has to call `SceneUserProperties.resolve` too, or it silently goes back to the stale value. A number bound to a vector field is repeated out to the authored component count. Scripts' `applyUserProperties` gets these values as well, not the script's own `scriptproperties`.

### Scene motion: evaluator vs. rasterizer

Scene playback is split so the animation work survives a change of renderer:

- **`SceneEvaluator`** (`SceneParsers/SceneEvaluator.swift`) — `(layers, time, cursor) → [ResolvedLayer]`. Depends on Foundation and CoreGraphics only; knows nothing about SpriteKit. `SceneLayerBinding` is the static half of a layer (authored transform, parallax depth, keyframe tracks), built once at load.
- **`WallpaperSKScene`** (`SceneParsers/WallpaperSKScene.swift`) — an `SKScene` subclass whose `update(_:)` writes each `ResolvedLayer` onto its node. `SceneWallpaperViewModel.buildSKScene` builds the node list and the binding list in one pass so their indices cannot drift.

Things that were expensive to establish, all measured against the installed library:

- **`general.cameraparallax` gates parallax, not the layer data.** Wallpaper Engine writes a default `parallaxDepth` of `1.0 1.0` onto most image objects, so 63 of the 76 scenes carrying depth values have the feature switched off by their author. Only 13 actually parallax. Ignoring the flag invents motion the author rejected.
- **Keyframe tangent `x` is a fraction of the segment, not a count of frames.** The Hermite term is therefore `y / x` — the segment length cancels. Reading `x` as frames makes the term scale with the segment and threw a 5634-frame track 150,000 units off screen.
- **An animated property keeps its authored `value` beside the `animation` block.** `relative: true` means the channels are offsets from it; absent means they replace it. Both forms occur, and swapping them either pins a layer to the origin or launches it off frame.
- **`startpaused` tracks must not play.** They are Wallpaper Engine's cursor-triggered hover reactions; running them on the clock sends UI elements sliding on load.
- **`SKRenderer.update(atTime:)` only forwards the first tick to the scene**, so an offline harness has to call `WallpaperSKScene.update(_:)` directly. `SKView` does drive it every frame — verified by presenting a real scene in a real `SKView` and watching layers move.
- **The cursor is polled, not observed.** Wallpaper windows set `ignoresMouseEvents`, and the global `NSEvent` monitor in `setEventHandler()` must keep its narrow mask; `NSEvent.mouseLocation` is a plain read, so sampling it once per frame adds no events.

### Script behaviours from upstream (`Services/SceneRuntime/`)

Upstream's 0.9.0 recognises three shapes of *moving* origin script with regular expressions and reproduces them in Swift, without running the JavaScript: a MapleStory `new shared.Mob({range, moveList, standList, speed})` (walks between bounds, faces its direction, picks its own sprite-sheet frame), the `MotionItem` helper (constant speed, wraps across the canvas), and a hand-rolled step-and-wrap with optional vertical bob and random restart height, whose numbers may come from scene-wide constants (`SceneScriptConstantsParser`). The sandboxed script runtime evaluates an origin script only when its result is a constant, so these do not overlap with it. `SceneWallpaperViewModel.scriptedMotion` builds the controller from the layer's holder as built, and `WallpaperSKScene.tickMotion` runs it *after* the evaluator and outside its static short-circuit, so the mover's position wins. Wallpaper Engine's scene space is already SpriteKit's (y up; `origin` is the holder's position as it stands), so the controllers' numbers go straight onto the node. A mob takes its frames from the layer's sheet, so the sheet does not also play on the clock. No scene in this library uses any of the three (0 movers across all 93 scenes), so they are verified by the test suite, not by `Tools/scenecheck`.

### Particles

`buildParticleNode` maps a Wallpaper Engine particle system onto one `SKEmitterNode`. The systems themselves are shared presets — `particles/presets/smoke1.json`, `raindownpour.json`, `fog2.json` — and a scene places the same preset a dozen times over, so almost nothing about how a layer looks lives in the preset.

- **`instanceoverride` is where the layer is actually configured**, and it carries far more than a rate: 418 of the library's 493 particle objects have one, spread over 58 scenes, with `rate` 231 times, `colorn` 186, `alpha` 178, `size` 159, `count` 143, `speed` 102 and `lifetime` 89. Every number in it *multiplies* the preset — values run from 0.03 to 20 and `alpha` reaches 5, which only reads as a scale factor. Honouring two of those fields is what buried The Batman under white smoke: its three `Smoke cloud` layers are authored at `alpha: 0.06` and tinted red, and at the preset's own full-opacity white they covered half a 4K frame.
- **A `Double?` on a field Wallpaper Engine sometimes writes as a string deletes the whole layer, silently.** The struct decodes as a unit, so one bad field throws past `WEParticleSystem` and `buildParticleNode` returns nil. It has now happened three times: `distancemax` (25 systems), the `instanceoverride` fields that arrive `{"user": .., "value": ..}` (23 objects), and `startvalue`/`endvalue`, which `sizechange` writes as numbers and `colorchange` as colours (30 emitters across 7 scenes, caught only because the node counts in the render report dropped). Decode these with `WEFlexValue` or the `flexible` helper, never a bare scalar.
- **`maxcount` is a budget, not a count**, and SpriteKit has no equivalent, so it becomes a birth-rate ceiling: `maxcount × instanceoverride.count / lifetime`. An overridden `lifetime` therefore has to be applied *before* the ceiling is computed, and an overridden `alpha` before `alphafade` reads `particleAlpha` back as its keyframe peak. The order in `buildParticleNode` is load-bearing in both directions.
- **The emitter's roll stays at zero.** `SKEmitterNode`'s emission angle is already a rough reading of WE's velocity initialisers; turning it by the object's own angle as well compounds two approximations, and several scenes carry emitters rolled 70° or more.
- **`eventfollow` children are declined, except the shooting-star rider.** `SKEmitterNode` gives no access to its particles, so nothing can follow one; the one shape that needs no access is `shootingstarglow` on `shootingstar` (same life, same fade, instantaneous, no motion of its own), which is merged into its parent's particle sprite as a second additive image — 3 of the library's 56 `eventfollow` children. Every other child, and all 31 `eventspawn` bursts, stay declined.
- **`particleScaleRange` is a ratio around `particleScale` 1**, so it must not carry `instanceoverride.size`: the override already reaches the particle through its size, and applying it to the range as well made `size: 3` on a 10–20 preset draw particles from nothing to twice their mean.

### Text layers and the scripts behind them

`SceneTextLayer` rasterises a scene's `text` objects — clocks, labels, music-player readouts — and `SceneScriptRuntime` runs the JavaScript that feeds them. Measured over the installed library: 386 text objects across 33 of the 94 scenes, of which 209 are visible and drawn (the rest are the unselected halves of user-switchable variants), and 119 of 120 registered scripts run.

- **`pointsize` is not a pixel size: glyphs render at `pointsize * 4`.** Derived by comparing every single-line literal against the box Wallpaper Engine baked beside it — the box came out 3.6–4.3× wider than the font measures at `pointsize`, and its height a flat 4.67× for FreePixel against 2.56× for Pixeltype. Both are the same constant seen through each font's own line height (1.17 em and 0.64 em); two unrelated fonts agreeing is what makes it a constant rather than a fit.
- **The authored box is the authority, so the font only ever shrinks to fit it.** 129 text objects name a face by family (`systemfont_consolas`, `systemfont_arial`) and Consolas is a Windows font, so the layout falls to a wider substitute. Lonely Cat's clock is the case: a 375-unit box holding "12:34", which SF Mono measures at 396, so it wrapped and the wallpaper showed "12:3" above a stray "4". The shrink is computed **once, from the baked string**, and kept for every later string: it corrects the face, not the text.
- **`size` is the extent of the baked string, not a wrapping bound.** `limitwidth` is off or absent on 348 of 386 objects; there a string breaks only at `\n` and the layer grows with it, because boxes are measured from placeholders — "DAY" — and wrapping at their width broke "SATURDAY" mid-word as "SATURD"/"AY" (Honkai, Angel, Road Infinite, Lost Landscape). With `limitwidth` on (38), lines break at `maxwidth` and only between words; `limitrows` + `maxrows: 1` cuts the line, with "…" when `limituseellipsis` says so.
- **Alignment is the anchor.** `horizontalalign`/`verticalalign` decide which edge of the text sits on the object's origin, not just where the text sits inside a box centred on it: Porsche 911 GT3's left-aligned clock starts at its origin in the preview, Pixels' world-clock column lines up only on left edges, and Winter Conch Street's top-aligned greeting lost its first line off the frame when centred. Set as the sprite's `anchorPoint`, so a script's wider string grows away from that edge.
- **`padding` is glyph-atlas padding, not layout.** It is a flat 32 on 333 of the objects, including one whose whole box is 14×23 — inset by 32 there would leave nothing. Ignore it; likewise `anchor`, which is `none` on 368 of 386.
- **Wallpaper Engine bakes the last string a script produced into `value`.** That is why a scripted layer renders at all without a runtime — and why it renders a clock frozen at the minute the author saved, which reads as more broken than a gap. 267 of the 280 wrapped text fields carry one.
- **The scripts are ES modules, and `JSContext` evaluates scripts.** `import`/`export` are stripped rather than resolved, and each script is wrapped in its own closure: they keep state in module-level `let`s and dozens reuse the same names, so one shared global scope would have the last-loaded script drive every layer before it.
- **Installing a `JSContext.exceptionHandler` stops the context populating `context.exception`.** Checking that property after installing a handler reports success for every script that failed. Record the exception in the handler instead.
- **`thisScene.getLayer` returns a real handle, and calendars depend on it.** It used to return null, so every script touching another layer threw on its first line: Fujiyama's calendar writes year/day/month into plain text layers by name, Pixels moves its "today" marker onto cell `C<day>` and its world clocks read an offset from a sibling, Winter Conch Street switches its holiday greeting. A handle holds plain values (`text`, `visible`, `alpha`, `origin`, `scale`, `getEffect(name).visible`); writes are recorded and applied by `WallpaperSKScene`, and nothing else is offered, so a script reaching for texture animation, sound or a parent still throws and keeps its baked value. `shared` is one object per scene, as in Wallpaper Engine.
- **Property scripts run live only when they read the calendar** (`Date` plus a field accessor, nothing cursor/media/audio/random), or read only `shared` keys such scripts write — 28 scripts in 3 scenes. Everything else stays load-time or baked; 11 scenes use `shared`, mostly for cursor and media state no one here writes. They are stepped at 60 Hz to rest before the first frame (easing scripts use `mix(v, t, speed * frametime)` and a single step would leave them a sixth of the way), then per 10 Hz poll. `defaults write … SceneScriptDate 2026-10-19` (or `-SceneScriptDate …` after the ids in `Tools/scenecheck`) shifts the scripts' clock, which is how the six other weekdays of a calendar are verified.
- Scripts are polled at 10 Hz and the raster only redone when the string changes; the whole runtime costs Pixels ~0.17 ms a frame across 32 of them. Untrusted Workshop code runs in a bare context — no DOM, no network, no file system — and a script is abandoned, leaving the baked string, when it throws or when it is interrupted: JavaScriptCore's own execution time limit (`JSContextGroupSetExecutionTimeLimit`, private, looked up with `dlsym`; JSC counts it per entry) stops one that loops at 20 ms a call and 100 ms for a module's top level, and a per-poll budget of 5 ms of *thread CPU* time abandons the costliest script once a poll passes it. Before that, the 20 ms budget was a wall-clock check made *after* the call returned, which a `while(true)` never does, so one looping script hung whatever thread was running it. `SceneScriptsDisabled` (Settings → General → Developer → Disable scene scripts, or `defaults write com.winddog.wallpaper-engine SceneScriptsDisabled -bool YES`, or `-SceneScriptsDisabled YES` to the tools) freezes them all, which is how a scripted layer is told apart from a mis-rendered one. It is `SceneQuality.scripts`, read per build, so the switch rebuilds the scenes showing; with it on, the builder creates no `SceneScriptRuntime` at all. On Pixels `Tools/scenecheck render` reports `mov= 0.19` with scripts and `0.00` without.

### Effects

`SceneEffectBuilder` turns a layer's `effects` array into nested `SKEffectNode`s — one per pass, innermost first — and `WEShaderTranslator` rewrites each pass's GLSL into SpriteKit's dialect. Measured over the installed library: 459 of 459 translated shaders compile, live in 68 of the 74 scenes that carry effects. Two HLSL leniencies had to be reproduced for the last two: stages may declare a varying at different widths (the wider wins and the fragment's bare uses are truncated back), and `lerp` truncates a wider weight (`mix(a, b, t)` gets `t.xyz` when that is the only way it can compile). Layer placement is unaffected.

The traps, all paid for once:

- **Wallpaper Engine ships its shaders CRLF, and `"\r\n"` is a single `Character` in Swift.** `split(separator: "\n")` therefore returns the whole file as one line and every line-based reader silently sees nothing. This bit twice: first in the translator, where no `#include` or `#if` was ever processed, and again in `SceneEffectBuilder.samplerCombos`, where the mask declaration went unseen so `MASK` stayed off and a painted tint flooded its entire layer with flat colour. Normalise line endings at the point of reading.
- **`SKShader` generates `uniform` declarations from its own `uniforms` array.** Declaring them in the source as well emits a second, malformed declaration (`uniform float g_UserAlpha[0];`) and fails the compile. Emit no uniform declarations; return the names for the caller to bind.
- **`main` is the only scope SpriteKit supplies anything to.** Uniforms, textures and varyings all arrive as members of a structure handed to the fragment entry point, so a free helper function referencing one compiles to an undeclared identifier. The translator declines such a shader rather than let it fail downstream — a declined effect skips cleanly, a failed compile costs the layer an offscreen pass that paints nothing.
- **`gl_FragColor` can be written but not read.** Wallpaper Engine reads it constantly — `gl_FragColor = mix(texSample2D(g_Texture0, uv), gl_FragColor, mask)` is how most of its passes blend against the layer beneath — and 26 shaders failed on a value they had just written. Every pass's body now runs through a local, `we_FragColor`, written out once at the end — once the alpha conversion below needed a single write-out point anyway, keeping two code paths stopped paying for itself.
- **Both stages' top-level definitions have to be folded in, not just the vertex `main` body.** A perspective transform calls `squareToQuad`, which the *vertex* shader defines; folding the call without the definition leaves it undeclared. Deduplicate by name — the two stages share headers.
- **SpriteKit is premultiplied at both ends of a shader; Wallpaper Engine is straight.** Measured with a probe: a white sprite at alpha 0.5 reaches the shader as (0.5, 0.5, 0.5, 0.5), and a shader writing (1, 1, 1, 0) paints white, because the result is composited `one, one-minus-source-alpha`. So every tint/noise/gradient pass that rewrote `rgb` over a transparent texel *added* colour to the frame — Sunset on Station's pale box, the white squares over 2847470774's player buttons, a cyan box around Hacker Apartment's perspective-mapped monitor. The translator now un-premultiplies every sample of `g_Texture0` and premultiplies (clamped) once at the write-out; for passes that only move texels it is the identity. **Auxiliary slots are deliberately left alone**: converting them too (they also sample premultiplied) put a striped block into 2607457838's grass, because noise maps keep independent data in alpha.
- **Strip comments before scanning shader code for identifiers.** `reflection.frag` keeps a commented-out line naming an undeclared `g_Additive`, and the undeclared-identifier check declined it for that. Stripping brought back 5 passes, which then exposed the next bullet.
- **Shader bodies run in WE's top-down texture space; every sample flips back.** SpriteKit's `v_tex_coord` runs bottom-up, so `a_TexCoord` becomes `we_TexCoord = (x, 1 − y)` and the prelude's `texSample2D` samples at `WE_SKSPACE(uv)`. Auxiliary slots flip too — masks are uploaded the same way up as the layer. A pass that samples where it stands is unaffected; every asymmetric `y` an author wrote was mirrored before: `reflection` painted a white blob over 1990 Miata's road and BMW's wet tarmac lost its tail-light reflection, which now matches the preview (it was declined by name until this; 459 of 459 now compile, the three `reflection`s included), gradients ran upside down (Simple Music Player's, against its preview), the light on ARK: Survival Evolved Girl with Raptors (973177888) sat at her feet instead of top right, as in its preview, and Hacker Apartment's perspective-mapped monitor came out split in two. Checked in a real `SKView` (`texture(from:)`) as well as `SKRenderer`: both put `v_tex_coord.y = 0` at the bottom. Motion was checked live too, because `SKView.texture(from:)` on a presented scene *does* advance `u_time`: block-matching 30 frames of 2553418404's scrolling sea gave 3634 blocks moving down against 65 up, its `preview.gif` (Wallpaper Engine's own render) 280 down against 23, and the build before the flip 43 down against 3443 up. Over the library `render` moves most scenes with an effect, so diff against previews, not against the old PNGs.
- **`M_PI` and `inverse` are not in this dialect**; Wallpaper Engine's own compiler supplies them. Emit each only when the shader asks for it and nothing else defines it, and rename `inverse` to a polyfill so it cannot collide with a builtin SpriteKit may grow.
- **Combos must be re-emitted as `#define`s**, not merely consumed by the conditionals: WE passes them as values too, as in `ApplyBlending(BLENDMODE, ...)`.
- **`SKRenderer.update(atTime:)` forwards only the first tick** to the scene, so an offline harness must call `WallpaperSKScene.update(_:)` directly. `SKView` does drive it every frame.
- **A pass costs in proportion to the area of the layer it wraps, not the size of the frame.** Measured with one `SKEffectNode` and one shader in a fixed 3840×2160 viewport: 4.49 ms at full size, 1.00 ms at 1920×1080, and a floor around 0.6 ms. SpriteKit sizes the render target to the node's contents **in the effect node's own coordinate space, ignoring every scale above it**: a pass over a 3840×2160 sprite under a 0.05 parent cost 3.67 ms a frame against 4.43 unscaled, for 141 pixels on screen. `renderEffectsAtDrawnSize` therefore moves a shrunken layer's drawn-size scale inside its chain (a node above the sprite shrinks it, a node outside the outermost pass scales it back; the two cancel, so placement cannot move) — only downwards, only where it at least halves the shaded area, never under a scale track. Dark Magic, two 3000×2000 layers drawn at 0.54 and 0.67 in a 1080p scene under eight animated passes, went 16.4 → 5.0 ms. It is not pixel-identical — fewer texels are sampled — and on Dark Magic moves 0.8% of the frame by more than 8 levels (max 60, edge and grain), which is why the floor is half the area: at 0.8 of the area it moved 2.7% of Houseki no Kuni's water for a fifth off. What *is* oversized is the artwork: across the eight most expensive scenes, 31% of the area under an effect falls outside the frame (0% in Sunset on Station and Retro Room, 57% in Honkai and Lonely Cat). Clipping the sprite geometry to reclaim it would change what `v_tex_coord` spans, and these shaders' UV *is* the layer — every gradient, vignette and mask would silently render against a different rectangle. Not worth it.
- **Effects are roughly 90% of the frame cost on the scenes that are expensive at all.** With `SceneEffectsDisabled`: Angel 27.6 → 2.9 ms, dragon-flames 25.3 → 5.5, Dark Magic 17.5 → 1.4, Honkai 16.1 → 2.8. Note that `Tools/scenecheck cost` renders at the scene's *authored* resolution, usually 4K; the app's `SKView` renders at the display's, so a 1440p screen pays roughly half of these. That holds for the composite; whether it holds for effect offscreens is unmeasured — an effect node ignores every node scale above it (previous bullet), and if it ignores the scene-to-view scale too, a 4K scene's passes cost the same on any display.
- **Each pass is an offscreen render, and `shouldRasterize` caches the pass's *input*, not its output.** What it keeps is the node's rendered children; the shader still runs on every draw over that texture. Measured in a real `SKView`: a cached node whose *own* shader animates with `u_time` animates exactly like an uncached one, while a cached pass-through *over* a `sin(u_time)` pass froze it at its first frame (centre texel 128 for 1.6 s, against 255 → 1 → 132 uncached) — nothing in the node graph changes when a shader beneath animates, so nothing invalidates the cache. Replacing a child's or grandchild's texture does invalidate it. So a pass is cached exactly when everything beneath it is still: no alpha track and no clock-reading pass inside it, whatever the pass itself reads. The old rule (cache when *this* pass reads no clock) got both halves wrong: it froze 19 passes in 10 scenes — Angel's sea and cloud bank, Honkai's figure and its cloth layers, dragon-flames' wing, Retro Room's alarm clock — and it re-rendered the sprite into an offscreen every frame under every animated pass sitting directly on a still layer. `WallpaperSKScene` also skips alpha writes that would not change the value, because an assignment dirties the node and throws the cache away.
- **The offline harness cannot see a frozen pass, and reports it as cheap.** `SKRenderer` never advances `u_time` (a `fract(u_time)` probe stayed 0 across `update(atTime:)` calls), so `render` draws every effect at t = 0 — frozen or not, the PNG is the same — and `cost` never re-renders the subtree under a cached node. Before the freeze was fixed Angel measured 33.7 ms; drawing its water and clouds as the app should costs 45.3, and caching inputs brought that to 39.1. Use a real `SKView` (an off-screen borderless window works) to check anything that depends on the clock.
- **Frame cost, ms at authored resolution, `Tools/scenecheck cost`, median of 3 interleaved runs on one quiet machine** (noise ±5%), for main before the integration branch → the integration branch → after the caching and drawn-size changes: Retro Room 3.20 → 9.56 → 7.74, Sunset on Station 10.89 → 13.83 → 11.14, Dark Magic 17.65 → 20.36 → 5.04, dragon-flames 25.61 → 30.49 → 28.79, Angel 32.37 → 33.74 → 39.06, Honkai 12.75 → 11.54 → 8.15, Hacker Apartment 6.27 → 3.02 → 1.83. Every regression in the middle column is fidelity, bisected over the first-parent merges: the lenient material decode (`d759cbc`) let waterflow and waterripple compile, adding two full-frame 4K animated passes to Retro Room's base layer, one to Sunset's full-frame layer, one to Dark Magic, four to dragon-flames and two to Angel's water; earlier, between `c6acf42` and `7141adc` (the visibility-inheritance merge), Dark Magic had lost 8 cached passes on layers it no longer builds. Angel's net rise is the price of its water and clouds moving at all. Particle prewarm (`advanceSimulationTime` once, at build), sprite-sheet frames (cropped at load; the two sheets that play swap a texture only when the frame changes), the straight-alpha conversion and the `we_FragColor` write-out cost nothing per frame and change no caching decision; hidden layers are never built.
- **Settings → Reflections is `SceneQuality.reflections`**, read by `SceneEffectBuilder.reflections`: off drops every effect whose material runs the `reflection` shader as if its author had hidden it — not tallied, so `Tools/scenecheck effects … -SceneReflections NO` reports exactly 456 of 456 against 459 (the three passes of 1990 Miata, BMW and Lonely Cat). Default on; enabled only while Post-Processing is, and `sceneQuality(onScreen:)` normalises it to on while effects are off so a preset touching only it does not rebuild every scene.
- Three classes are declined rather than approximated, each after watching it damage a wallpaper: multi-pass effects (a combine pass needs both the cast result and the untouched layer), audio-reactive effects (compiling the audio variant out pins the response to zero, which scales some layers to nothing), and sampler slots with neither an assigned nor an annotated texture.
- **A declined audio *generator* takes its blank canvas with it; a declined *modulator* does not.** Audio visualisers are a white solid layer (or a flat-white texture) under a fork of the Workshop's `Simple_Audio_Bars`, which reads `g_AudioSpectrum…` in the fragment stage with no `AUDIOPROCESSING` switch and, on `TRANSPARENCY` 1 or 4, sets the layer's alpha to the bar coverage — so at silence Wallpaper Engine draws nothing there (the `enhanced` fork's rounded caps leave a row of dots, which is lost). Declining the pass used to leave the bare canvas: 10 white rectangles across 7 scenes (Sunset on Station, Pixels, Honkai, Lost Landscape, Good rest, Apple Music, Hacker Apartment). `SceneEffectBuilder.isDeclinedAudioCanvas` now drops those layers, and only those: textured layers holding a picture are kept whatever is on them, `pulse`/`shake` (spectrum read in the vertex stage, behind `AUDIOPROCESSING`) are untouched, and `SceneEffectsDisabled` brings the canvases back. The triage's "Road Infinite, Other World, Final Demons" canvases sit under a `musicplayers` group their authors ship off, and were never drawn.

`SceneEvaluator.isStatic` short-circuits the whole per-frame path for scenes with no parallax and no tracks, which is most of the library.

### Framebuffer blend modes

`colorBlendMode` is the layer's compositing mode, numbered as in WE's `shaders/common_blending.h`. Multiply, screen, add and subtract map onto `SKBlendMode`; the rest (overlay, soft light, lighten, colour dodge, tint, …) read the frame beneath the layer, which SpriteKit never hands a sprite. `SceneBackdropBlend` does them exactly where that frame is a constant: when nothing beneath the layer can change (`blendAgainstStaticBackdrops` lists the rules), the backdrop is rendered once at load through `SKRenderer` and the layer's shader applies WE's own formula against it. Elsewhere they stay normal alpha.

- **Emit `F` premultiplied by opacity and let source-over add the rest.** WE writes `mix(A, F(A, B), opacity)` opaque; emitting `(F·op, op)` gets the `A·(1−op)` term from the *real* framebuffer, so the snapshot only matters under the layer's own pixels and never paints the backdrop back at the snapshot's resolution.
- **Verified by passthrough, not by eye:** a shader that paints the sampled backdrop over the whole quad reproduces the frame with the layer removed to 0 levels on Porsche 911 and Lancer X (mean 0.10 on Angel, whose layer goes through its effect chain's offscreen and is resampled). The arithmetic was checked on flat synthetic layers to the level.
- **Read pixels raw when checking colour.** `NSBitmapImageRep.colorAt(…).usingColorSpace(.deviceRGB)` converts through the PNG's profile, and made correct overlay output read 20 levels off the formula. `getPixel` does not.
- **Re-tinting a text or solid layer is wrong**: their colour is baked in, so the blend shader inherits only the tint shader's `u_tint`. A scripted layer (Porsche's clock) has its map recomputed on every resize, against a full-width backdrop band.
- Measured: 18 built layers in 6 scenes ask for these modes; 4 qualify. The rest sit over an animated layer (Razer Quartz Lair's nine, over its wave), move (Valley's flare), sit by a script (two in Lancer), or draw nothing. 30–60 ms of snapshots per scene at load. Per frame it is free on a plain sprite, but a layer with an effect chain needs one more offscreen pass around it: Angel's full-frame water costs 53.8 → 60.1 ms a frame at 4K (3 interleaved runs), because its chain reads the clock and cannot be cached.

Scenes are parsed and built on a per-model serial `loadQueue`, never on the main thread (it used to freeze the app for up to several seconds per screen), with a generation counter so a superseded build is dropped; only the `skScene` assignment hops to main. A scene with no motion, emitters, scripts or clock-reading pass publishes `isStill`, and `SceneWallpaperView` then stops rendering it after a few frames (`shouldRender`), instead of re-compositing the same 4K frame all day. A scene that cannot be loaded at all publishes its preview rather than leaving the previous wallpaper on screen.

### Steam Workshop

Two independent services, wired together by `WorkshopViewModel`:

- **`WorkshopAPIService`** — browsing, via `IPublishedFileService/QueryFiles` for app 431960. Requires a user-supplied Steam Web API key, stored in `UserDefaults` under `SteamWebAPIKey`. Text search forces `query_type = 12`.
- **`SteamCmdService`** — downloading, by spawning an external `steamcmd` binary (auto-detected across Homebrew/Steam/standalone paths, or `SteamCmdPath`). Downloads land in steamcmd's `workshop/content/431960/<id>` and are then copied into `wallpapersDirectory`. All `Process` invocations must read stdout/stderr concurrently with a timeout — steamcmd fills the pipe buffer and deadlocks otherwise; `runSteamCmd` is the pattern to copy. A download is bounded by an inactivity timeout and can be cancelled, and steamcmd is ended 10 s after it prints `Downloaded item <id>`, because on macOS it often hangs on its way out after a finished download (found upstream, Unayung/wallpaper-engine-mac PR #2) — before that the inactivity timeout caught it three minutes later and reported a complete item as failed; it is imported off the main thread into a hidden staging folder and swapped in, so an updated item replaces the old files instead of being skipped, and `.workshopItemImported` refreshes the library and reloads any screen showing it.

Steam's `QueryFiles` has no exclusion parameter — every tag it accepts is *required* and they AND together. So content rating and type are single-choice controls, and excluded genres (`WorkshopExcludedTags`) are filtered out client-side after results return, with `hiddenByExclusion` reporting the shortfall.

### Persistence

Everything is `UserDefaults`; there is no database or config file.

| Key | Meaning |
|---|---|
| `ScreenWallpapers` | `[screenId: WEWallpaper]`, JSON. Keys containing `_` are stripped on load (dead per-space experiment) |
| `CurrentWallpaper` | Legacy single wallpaper; still written for backward compat, migrated on first load |
| `EnabledScreens`, `DisabledScreens`, `RecentWallpapers`, `PlayVolume` | Per-screen enablement, screens the user switched off (kept off on reconnect), recents (max 10), last volume (never written while auto-muted) |
| `GlobalSettings` | The whole `GlobalSettings` struct, JSON. Decoded field by field; `qualityRevision` decides which quality fields of an older save are honoured (revision 2: `reflections` from before it is ignored, since the toggle was a constant until then) |
| `OSWallpapers` | `[screenId: URL]`, each screen's real desktop picture (`DesktopPictureLedger`), restored on quit. Migrated from the legacy single `OSWallpaper` |
| `TrustedWallpapers` | Allowlist of web/application wallpaper paths the user approved |
| `SteamCmdPath`, `SteamLastUsername`, `SteamWebAPIKey`, `WorkshopExcludedTags` | Workshop integration |
| `WallpaperEngineAssetsPath` | Override for the shared WE asset library (Settings → General → Developer); ignored while the path does not exist |
| `WallpaperLibraryPath` | Override for the library folder (Settings → General → Library), a path; absent means `~/Documents/Open Wallpaper Engine`. Ignored, never created, while it does not exist |
| `SceneScriptsDisabled` | Freeze every scene script at its baked value (Settings → General → Developer); removed rather than written `NO` when switched off |
| `FR*`, `SortingBy`, `SortingSequence`, `ExplorerIconSize`, … | UI state via `@AppStorage` |

On quit, `applicationWillTerminate` restores each screen's picture from `OSWallpapers` and deletes the cached `staticWP_*.tiff` placeholder images the app writes to the caches directory (used to tint the menu bar to match the wallpaper).

### Localization

`Localizable.xcstrings` (String Catalog), source `en`, with `zh-Hans` translations. Menus and other AppKit strings use `String(localized:)`. The app follows the system language; `GlobalSettings.language` is kept for decoding but has no control, and General instead opens System Settings' Language & Region pane (`x-apple.systempreferences:com.apple.Localization-Settings.extension`), where macOS keeps per-app languages.

### Entitlements

**Not sandboxed** (`com.apple.security.app-sandbox = false`) — required to spawn `steamcmd`, write outside the container, and set the desktop picture. Hardened runtime is on. TCC usage strings for Documents and Downloads are in `Open-Wallpaper-Engine-Info.plist`, which also carries an ATS exception for `haren724.top`.

## Conventions

- **Commits** follow Conventional Commits with a scope drawn from the subsystem: `fix(power):`, `feat(workshop):`, `fix(scene):`, `fix(tcc):`, `chore(signing):`.
- **Comments in this codebase explain *why*, often at length**, and frequently encode a bug that was expensive to find (the `AppDelegate.shared` re-entrancy trap, the sleep-notification pairing, the lossy `project.json` round-trip, the `NSEvent` mask, the steamcmd pipe deadlock). Preserve them when refactoring, and match that register when adding non-obvious code — short *what* comments are not the house style.
- Upstream code carries Chinese comments; new comments are written in English.
